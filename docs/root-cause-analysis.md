# Root Cause Analysis: System Defects & Architectural Hardening

This document outlines the systematic investigation, root-cause identification, and engineering remediation of the core defects previously affecting HNA / HINA.

---

## 1. Defect: Silent Response Compaction & Truncation

### Symptoms & User Impact
The user observed: *"Sometimes that whole content report gets compacted into a small thing, bro. What the fuck is that?"*
Detailed technical analyses, structured markdown tables, multi-section architecture overviews, and code blocks generated by the agent were abruptly truncated into a brief generic summary when rendered in the UI or reloaded from history.

### Root Cause
In `apps/api/hinaa_api/services.py`, an aggressive post-processing method `_trim_display_for_chat` was applied to all assistant responses before returning them to the frontend.
The method contained heuristic truncation logic:
```python
# Truncate at first double newline after header or bullet list
if line.startswith("##") or line.startswith("- "):
    ...
    return "\n".join(kept_lines) # Silently discarded 80%+ of content!
```
This conflated two completely separate requirements:
1. **Conversational Speech**: The audio channel needs to be brief, natural, and friendly.
2. **Text Display**: The chat interface needs to display the complete, unabridged, structured output with full fidelity.

### Verified Fix
1. Refactored `services.py` and `answer_depth.py` so that full structured `displayText` is preserved canonically by default for all responses (technical, multilingual, architectural, research, and conversational).
2. Completely removed destructive display trimming coupling (`_trim_display_for_chat`), ensuring `displayText` remains unabridged while the spoken channel (`spokenText`) independently receives conversational brevity.
3. Added comprehensive regression tests in `apps/api/tests/test_response_quality.py` and lifecycle tests in `apps/api/tests/test_response_lifecycle.py` verifying full markdown preservation across tables, headings, code blocks, citations, persistence, and reload.

## 2. Defect: Stripping of Indentation Inside Code Fences

### Symptoms & User Impact
When Hina generated code (Python, Rust, YAML, JSON), the rendered output had all indentation stripped to a single space, rendering Python indentation invalid and JSON unreadable.

### Root Cause
In `services.py`, the text cleanup routine `_clean_natural_speech_and_display` ran a blanket whitespace compression regex across all lines:
```python
line = re.sub(r"[ \t]+", " ", line)
```
This regex did not track whether the parser was currently inside a markdown code fence (```` ``` ````).

### Verified Fix
Implemented a stateful code fence detector supporting both backtick (```) and tilde (~~~) fences, language tags, and unfinished fences:
```python
fence_pattern = re.compile(r"(```[\w-]*|```|~~~[\w-]*|~~~)")
parts = fence_pattern.split(cleaned)
if len(parts) > 1:
    cleaned_parts = []
    in_fence = False
    for part in parts:
        if part.startswith("```") or part.startswith("~~~"):
            in_fence = not in_fence
            cleaned_parts.append(part)
        elif in_fence:
            cleaned_parts.append(part) # Preserve exact indentation and tabs
        else:
            cleaned_parts.append(re.sub(r"[ \t]+", " ", part))
    cleaned = "".join(cleaned_parts)
```
Verified via `test_preserves_code_indentation_inside_fences` and `test_response_lifecycle_backtick_and_tilde_code_fences`.

## 3. Defect: Model Registry Inaccuracies & Fictional Model Identifiers

### Symptoms & User Impact
The model registry contained speculative or non-existent model IDs (`agnes-2.5-flash`, `gpt-6-astra`, `claude-fable-5`) and lacked validated metadata for current frontier models (`gemini-2.5-flash`, `gemini-2.5-pro`, `claude-3-7-sonnet-20250219`). This caused routing failures, unexpected fallback, or provider errors.

### Root Cause
Lack of verified capability discovery and static hardcoding of experimental mock identifiers in `apps/api/hinaa_api/harness/model_registry.py`.

### Verified Fix
1. Updated `model_registry.py` with verified production specifications:
   - `gemini-2.5-flash`: 1,048,576 context tokens, 65,536 output tokens, vision + audio support.
   - `gemini-2.5-pro`: 2,097,152 context tokens, 65,536 output tokens, deep reasoning support.
   - `claude-3-7-sonnet-20250219`: 200,000 context tokens, 64,000 output tokens, hybrid thinking.
   - `llama-3.3-70b-versatile`: 128,000 context tokens, high-speed open routing.
   - `gpt-4o`: 128,000 context tokens, multi-modal.
2. Verified via 8 regression tests in `apps/api/tests/test_hina_harness.py`.

## 4. Defect: Provider Auto-Priority Inversion in Frontend

### Symptoms & User Impact
Automatic provider selection was forcing low-tier or unauthenticated fallbacks instead of choosing optimal gateway providers, causing test failures in `resolveProviderSelection.test.ts`.

### Root Cause
A previous commit reordered the `AUTO_PRIORITY` array in `apps/web/src/features/providers/utils/resolveProviderSelection.ts`, forcing `real` to the top and violating the architectural tier priority (`cx-gateway` -> `claude` -> `experiential` -> `codecraft` -> `real`).

### Verified Fix
Restored the canonical priority order in `resolveProviderSelection.ts`.
Verified all 20 test cases in `resolveProviderSelection.test.ts` pass cleanly.

## 5. Defect: Teletype Sound Leaking Beyond Turn End

### Symptoms & User Impact
Users reported that the typing audio feedback would continue playing or click indefinitely even after Hina had finished generating her answer.

### Root Cause
In `apps/web/src/design-system/modes/WorkMode.tsx`, the `playStreamChunkSound` function was triggered on text state changes without asserting that the agent was actively in a `speaking` or `thinking` state.

### Verified Fix
Gated the audio player check:
```typescript
if (isVoiceSessionActive && (isSpeaking || isThinking)) {
  playStreamChunkSound();
}
```
Audio feedback ceases immediately when the turn completes or transitions to `IDLE`.

## 6. Defect: Ephemeral Cloudflare Tunnel Dependency in Production Deployment

### Symptoms & User Impact
Production frontend hosted on Vercel lost all backend connectivity whenever the developer's laptop tunnel closed, causing 502 Bad Gateway and connection timeouts.

### Root Cause
Both root `vercel.json` and `apps/web/vercel.json` had hardcoded `https://framed-parker-atm-consider.trycloudflare.com` as the rewrite destination for all `/api/*`, `/v1/*`, and `/health` routes.

### Verified Fix
Replaced the ephemeral tunnel URLs with the dedicated production backend host `https://hinaa-api.onrender.com` (configured in `render.yaml`).
